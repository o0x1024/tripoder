# H2c 非协作调用与专属页发布

日期：2026-10-15。固定设备、普通 non-debuggable 独立进程、自有 ELF、`uint64_t(uint64_t)`、专属 4096 字节页。[JIT/AOT 证据](evidence/self-hook-h2c-2026-10-15/README.md)。

## 从执行位置证明可变范围

夹具目标固定为 `BTI c; ADD x0,x0,#1; RET`。唯一覆盖指令是 +4 的 ADD，入口 BTI 和 +8 的 RET 始终不变。暂停在 +4 的线程恢复后可进入新 replacement；已执行 ADD、暂停在 +8 的线程仍按旧调用返回。稳定跳板的回跳地址同样是从未修改的 +8。测试允许发布前已进入的旧调用按旧版本完成，但每次调用只能执行一次原函数。

跳板、relay、callback 和模块租约跨所有发布保留。仅在停止并 join 所有可能调用夹具的自有工作线程后，恢复原文件映射并释放租约；不会以回调计数为零推断未知调用栈已消失。此证明依赖夹具的完整调用者集合、专属页和固定叶函数，不外推到共享 libc 页、任意函数栈帧或第三方模块卸载。

## 复用同一个发布实现

`code_page.c` 拆为 prepare/commit/finish/cancel，原 H2a 协作域也调用这条路径，不保留第二套发布后端。

1. prepare 在线程正常运行时完成来源身份检查、私有 RW 候选页、RX 转换、内容和权限检查。
2. H2b 确认所有其他线程暂停后，`page_commit.c` 重新比较目标及候选页的全部 1024 个指令字；只执行直接 mremap 系统调用和 AArch64 cache maintenance。
3. 恢复线程后，finish 检查最终 RX/匿名映射及全部字节，更新唯一的页所有权统计。
4. 暂停失败或提交前内容不符，目标不写入，恢复后回收候选页。FIXED 发布出现不明结果时直接退出本独立进程，不恢复业务执行。

提交关键区的函数与 cache helper 纳入 ELF 反汇编调用白名单。暂停中没有 libc/JNI/分配器/stdio。来源映射的归属依靠受控夹具的唯一发布者和显式 dlopen 租约；当前不授予任意共享页发布能力。

## 验收

- 四个线程直接调用真实 ELF 入口，没有逐次 enter/leave、mutex admission 或调用方 ISB。
- 各 50 轮入口安装与停用，共 100 次目标页提交；跳板另发布一次。
- 故意阻塞信号导致准入失败：已准备候选页被回收，目标原值与原映射保持。
- 故意破坏事务中的预期字节：暂停期间拒绝，未执行 mremap，目标保持原状。
- 明确等待旧 callback 进入测试保持点，再撤销目标入口；旧 callback 后续完成且原调用仅一次。
- 每次原调用与 replacement 都检查返回值、原调用次数、errno；最后 join 调用线程、恢复两个文件页、确认模块实际卸载。
- 原 H2a 与 ART 既有检查在同一构建中全部回归。

未完成：共享页归属、多目标原子发布、完整 ABI/寄存器、BTI/PAC/MTE 硬件强制检查、异常展开、任意模块加载代次与长期稳定性。这些门槛没有因本阶段通过而取消。
