# 通用探针验收

本轮构建并安装单 APK，使用独立 stdio MCP 客户端操作自研测试 APK，无配对或手机脚本审批。完整结果见 validation.json、desktop-result.json、device-result.json 和 mcp-transcript.json。

- 37 项新链路检查通过：默认 thin 无加载器探针/扫描/写线程，启动脚本在 Application 调用前生效，初始化阶段的内存/文件加载器被发现，引用稳定且新进程拒绝旧引用，DEX 分页不丢失/重复，动态类 Hook 实际返回修改结果。
- 内存与文件 DEX 的自动快照、MCP 主动快照、Hook 脚本触发快照均通过。导出字节与独立 payload.dex 的 SHA-256 一致；同操作 ID 不新增产物，设备端配额拒绝不增加产物。
- Agent 通过通用工具停止准确安装、启动新进程、停用探针，停止操作重试复用回执。原 worker 退出后仍可查询和读取持久化产物。
- 原控制面 71 项、原 MCP Hook 链路 20 项通过。TypeScript SDK 40 项、桌面 MCP 12 项、Java 脚本契约 715 项通过。产品 Native 合约和 JNI 声明/导出检查随构建通过。
- 源码、APK、实际加载的 Native core 和进程身份由构建回执及映射核对；不是仅验证安装或界面启动。

普通 thin 的 JIT/AOT 策略和固定绑定数保持一致。记录的自研 APK 启动时间是单次观测，不能代替网易云或原生性能 A/B 验收。未进行 Sentinel 桌面模型实际调用、第三方壳恢复、CompactDEX 或方法体重建验收。

## 保留的失败证据

早期轮次没有覆盖为通过结果：

- 01–02：自研文件加载夹具的路径式只读设置未生效，改为对已打开 FD 设置实际只读权限，继续验收真实文件加载器。
- 03–04：新增 boot 探针成员尚未进入显式适配器准入，且 Android boot loader 不能用普通 JVM 的 null 假设判定。改为验证实际 boot 类身份，仅放行四类标准 DEX 加载器的构造和准确 addDexPath 签名。
- 05：单独观察 BaseDexClassLoader 入口漏过该设备的子类构造路径，增加标准子类入口；没有通过全局退优化规避。
- 06：客体命名空间拒绝宿主产物目录写入，保留原路径策略，改为由 authority 签发准确进程代次的目录 FD，使用受限文件名原子写入。
- 07–09：逐步验收了正确的目录写入、通用启停、分页与后台落盘。10 增补了主动快照、设备配额和退出后产物清单检查。
