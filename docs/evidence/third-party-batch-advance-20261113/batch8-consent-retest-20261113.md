## 2. 唯品会：「同 意」中间有空格

`Button` 的真实 label 是 **`同 意`**（两个汉字之间一个空格）。这解释了历史上三次失败的全部原因：

- `uiautomator dump` 的文本按空白切分后只剩「同」，所以旧脚本打印出 `Button 同`，看起来像文案被截断；
- 精确匹配 `text == "同意"` 打不中；
- 包含匹配 `"同意" in "同 意"` 也打不中（空格把它们分开了）；
- `grep -E "同意"` 同样看不到这一行。

**所以「唯品会不同意按钮找不到」从来不是应用缺陷，是我们用「连写」的假设去匹配一个「分写」的标签。** 修法是把两边都去掉空白再比较（`''.join(label.split())`），本轮已落到 `guest_ui.py`。

## 3. 这一轮把文本匹配的四个坑全部踩了一遍（都写进工具了）

按踩到的顺序：

1. **精确匹配打不中分写标签** → 引入 `tap~` 子串匹配。
2. **子串匹配先命中说明段落**：唯品会隐私页的正文段落也包含「同意」，且 dump 顺序在按钮之前，于是点到了段落 `[223,878][985,1448]` → 改为「按控件类型优先 + 文本最短优先」打分（Button 优先，短标签优先）。
3. **子串匹配打中否定控件**：`"同意" in "不同意"` 为真，于是**点到了「不同意」** → 增加「标签里出现 `不`+目标词就跳过」。
4. **分写标签**（本节第 2 点）→ 去空白归一化。

另外加了两条：

5. **行被视口裁剪**：列表底部那一行只报 3–6px 高，中心点落在手势条上，tap 无效 → `tap --scroll` 遇到高度 < 60px 的行先滚动再点。
6. 反过来的测试也做了：淘宝首轮 `not visible` 两次滚动后才点中 `[42,436][396,868]`（高 432px，正常）。

## 4. 边界

- 唯品会的「登录入口」是按文案定位到的浮层（`登录有机会领取惊喜优惠`），**没有点它、没有走登录闭环**。
- 淘宝「已启动未取证」不能写成「淘宝卡在同意页」：top 已是客体 Activity，但 dump 里没有同意类文案，两种可能（页面还在加载 / 同意层是 WebView 导致 dump 不可见）本轮未区分。
- 闲鱼是**列表可及性**问题：这一轮的失败发生在「点开应用」之前，与闲鱼自身无关。要修的是双向滚动（当前只会往一个方向 swipe），本轮没做。
- 携程仍无结论，不做推断。
- 工具改动（`guest_ui.py` 的 `tap~`/`tapxy`/裁剪检测）已入库，后续批量推进可以直接复用；`tap`（精确）保持原语义不变，避免影响既有脚本。
