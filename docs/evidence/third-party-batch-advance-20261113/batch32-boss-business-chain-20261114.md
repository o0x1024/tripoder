## 2. 方法学（本轮新增两条可复用判据）

### 2.1 逐页 dump 取 bounds 取代坐标猜测

上一轮失败的全部原因是复用旧坐标：`女 (866,1377)`、`确认 (1018,999)` 在真实布局下分别落在别的控件上。
正确做法是每页先 `uiautomator dump` 拿 `bounds` 再算中心。本例命中：
- 男 chip `[96,1415][586,1582]` → `(341,1498)`
- 下一步 Button `[60,2402][1148,2534]` → `(604,2468)`
- 「不是」`[619,751]…` 行 → `(867,820)`

### 2.2 「EditText 页禁 dump」的规则是错的，边界在应用不在控件

本轮在含 EditText 的页面（姓名、公司搜索、工作内容、学校、专业、个人优势）连续 dump 20+ 次，**客体进程全程健在**，`bounds` 全部可读。
真实边界是：某些应用（微博/拼多多）的输入页会经无障碍预取 → 剪贴板 `hasPrimaryClip` → AppOps 校验杀死客体；BOSS 不走这条路径。

⇒ 判定前应实测「这一页能不能 dump」，而不是按「有没有 EditText」一刀切。

### 2.3 wheel 类控件在这里是普通 RecyclerView

出生年月 / 入职离职时间是「年月」双列滚动列表，**tap 中间行即选中**，不需要 drag。
实测：入职时间列 tap `(734,740)` 后，离职列由「7月/至今/7月」自动切为「至今/8月/2026年」，随后「下一步」可用。

## 4. 边界

- 本批未发送自定义文字消息（只发预置打招呼语）；输入框 `介绍自己回复率更高哦~` 已定位，文本发送未测。
