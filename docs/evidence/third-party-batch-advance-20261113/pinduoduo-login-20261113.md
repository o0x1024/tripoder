红包动画的渲染状态会让整块内容上下漂 ~300px，**同一个坐标一次有效一次无效**（14:34 那次点在空白处，页面无变化）。
所以这类页面必须「每次点击前重新取证」，不能复用上一轮坐标。

## 4. 剪贴板崩溃族在拼多多上二次复现（重要）

本应用给出这条族最干净的分界证据：

- 14:29 在**登录页**（只有按钮，无 `EditText`）执行 `uiautomator dump`：**成功**，返回完整子树与 bounds。
- 14:32 点「手机号」进入**手机号页**（有 `EditText`）后再 dump：

```
FATAL EXCEPTION: main
Process: com.xunmeng.pinduoduo, PID: 16361
java.lang.SecurityException: Package com.xunmeng.pinduoduo does not belong to 10542
  … TextView.canPaste → ClipboardManager.hasPrimaryClip → system_server
    ClipboardService.clipboardAccessAllowed → AppOpsManager.checkPackage
```

⇒ **判据不是「哪个应用」，而是「目标页有没有输入框」**：`TextView.onInitializeAccessibilityNodeInfoInternal`
在有无 `EditText` 时都会走 `canPaste()`，但只有输入框会把「粘贴」动作真的暴露出去并走到剪贴板服务。
这条同时解释了微博（登录页崩）与拼多多（登录页不崩、手机号页崩）两个观测，落在同一条 C1 身份事实上。
修法候选仍是「剪贴板门面化」，判据见 [weibo-login-20261113.md](weibo-login-20261113.md) §4 末。

## 5. 操作口径（本轮定稿）

- 目标页**没有** `EditText` → 可以 `uiautomator dump`，用文本+bounds 驱动，最稳。
- 目标页**有** `EditText` → 只能 `screencap` + `input tap` 坐标 + `input text` 分段写入，**全程不 dump**。
- 长数字串必须分段（3–4 位）写入，一次长串会被截断（微博实测只进 `153`）。
