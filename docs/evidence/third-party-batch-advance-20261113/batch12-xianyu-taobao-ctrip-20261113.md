# 第 12 批：闲鱼 / 淘宝 / 携程 收尾（同意层与登录入口）

日期：2026-11-13
镜像：`build-opid-v82`（`HOST_OP_PACKAGE=true`、`PROBE=false`）

## 1. 要解决的问题

第 8 批结束时这三个应用只剩「无结论」，原因都是观测手段而不是应用行为：

- 闲鱼：Workbench 列表里取不到行（单向滚动 + 文本精确匹配）；
- 淘宝：启动了但 dump 里没有「同意」文案，被判成「没有同意层」；
- 携程：启动后没等到页面，记为「无结论」。

本轮用三段脚本收口：`/tmp/closing3.py`（双向滚动定位 + 60s 等待 + WebView/EditText 计数）、
`/tmp/closing3b.py`（点「我的」tab 取登录入口）、`/tmp/closing3c.py`（被挡住时的重试 + 底栏坐标修正）。

## 2. 方法上的两处修正

1. **双向滚动取行**：列表先向下翻 4 次（`swipe 540 1900 540 900`），不中再向上翻 6 次
   （`swipe 540 900 540 1900`），每次翻完重新 dump。单向滚动只能覆盖「目标在当前视口下方」这一种情形。
2. **用节点类型区分同意层**：dump 里统计 `android.webkit.WebView` 与 `android.widget.EditText` 节点数。
   WebView 同意层的条款文案由网页渲染，原生控件天然为空——这正是上一轮「淘宝没有同意文案」被误判的机制。
   只有 `webview=0` 且 `agree` 有候选时，才认为存在可点的原生同意层。

## 4. 三个结论

### 4.1 淘宝与携程没有隐私同意层，此前「找不到同意按钮」是判断错误

两者冷启后直接落在首页 feed，页面里既没有同意类文案，也没有 WebView 节点。
所以第 8 批把它们记成「已启动无同意文案」「无结论」是**观测口径错**（当时只找文案，没找页面形态），
不是这两个应用缺少同意步骤。以后判这类页面的口诀：先看 `webview` 与 `agree` 两个计数，再谈点不点得到。

### 4.2 携程登录入口已定位且可导航

「我的」tab（`[1084,2430]` 附近）→ 未登录态页顶部有
「登录携程，开启旅程」与「登录/注册」，点击后 Activity 从 `TaskP0$F0M0C2` 变为 `TaskP0$F0M2C2`，
说明这是真实可用的登录入口，不是装饰文案。

### 4.3 闲鱼的阻断是容器准入栅栏，不是闲鱼兼容性问题

启动被 Workbench 弹出：

```
应用没有启动
有一个更早的操作没有确认结果，暂时挡住了这次操作。请稍后重试
[知道了]
```

点「知道了」后**重试一次仍超时**（top 停在 `WorkbenchActivity`），crash 缓冲为 0。
这行文案对应 `ExecutionContract` 的 admission 拒绝（进程级栅栏），与 h26/h28 描述的机制同族：
只要本进程账本里有一条「结果未确认」的操作，之后每次 accept() 都被拒。

**关键新事实**：`force-stop dev.tripoder.q6 + q7 → 重开 Workbench → 两次「重新连接」` 之后栅栏依然点火，
说明 `BroadcastLedger.recover()` 把非终态行转成 UNKNOWN 之后，这些行仍然参与栅栏判定。
也就是说：**批量推进工作流本身会持续制造能挡住下一次启动的行**，这与「闲鱼不兼容」是完全不同的结论。

## 5. 复现

```
python3 /tmp/closing3.py     # 三个应用：双向滚动定位 → 60s 等待 → 首页 WebView/同意层计数
python3 /tmp/closing3b.py    # 点「我的」tab 取登录入口
python3 /tmp/closing3c.py    # 被栅栏挡住时点「知道了」重试一次 + 底栏坐标修正
```

脚本依赖 `android/scripts/guest_ui.py`（`adb`/`nodes`/`center`/`tap`），设备序列号 `d861a4fa`、宿主 `dev.tripoder.q6`。

## 6. 边界

- 淘宝的登录入口本轮**没有取到**：底栏「我的淘宝」在 round 2 的 dump 里存在（中心 `(1087,2480)`），
  但点击后 top 不变；round 3 重新 dump 时该文案已不在节点表里（首页 feed 重绘/懒加载）。
  这是「小尺寸或自绘控件点击不响应」族（同微信「用短信验证码登录」、快手登录胶囊）的又一例，未定位到根因。
- 闲鱼的登录入口与同意层本轮完全没有触达：卡在启动前的栅栏，属于容器侧，需先修栅栏再看。
- 三个应用的登录**流程**（点进登录页之后的运营商一键登录/验证码）本轮未测，本批只负责「入口能否到达」。
