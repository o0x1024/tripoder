## P0 通过的含义

P0 只证明一台指定设备上的受控能力切片。不能因此宣布通用 APK 支持、四大组件完整、恶意 APK 隔离、商用就绪或四款目标应用可用。

若非公开 API、Activity attach、真实跨应用返回或 Native 装载被设备阻止，记录具体失败边界并停止扩展能力，不换旧后端；仍可完成契约测试和失败证据，但 P0 结论必须为未通过或部分通过。

## 证据规范

每份验收绑定：源码摘要/HEAD 与工作区差异、宿主 APK SHA-256、客体 APK SHA-256、证书、设备 build fingerprint/API/ABI/页大小、宿主/客体 PID 和 UID、space/install/session generation、操作 ID、脚本版本、时间、断言、实际观测、结论。

区分 source-present、host-tested、device-tested、not-tested。测试进程只能写观察值，汇总器必须逐断言判定；异常、超时、丢报告不能算通过。证据不可包含 API 密钥或用户应用数据。

性能预算在 P0 建立基线后冻结。候选门槛（尚非已测结果）：100 次启动、10,000 次组件往返、1 小时合成压力；目标游戏平均 FPS ≥ 系统原生的 90%、p95 帧时 ≤ 115%；启动/内存/Hook 延迟单独设预算。不用数字替代交互正确性。

本轮实现与结论见 `docs/evidence/runtime-p1-2026-10-14/`。下一步为 P2 通用组件；整机断电与任意指令位置中断、真实用户项目迁移仍未验证，不直接扩大营销支持范围。
