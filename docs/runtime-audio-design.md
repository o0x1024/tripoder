# 音频能力边界

2026-10-15，微信第十三次在 Application.onCreate 获取 audio 服务时失败。本批原生对照 64 项、完整 runtime P2 587 项已通过，证据见 `docs/evidence/runtime-p2-plus-2026-10-14/audio-scalar-baseline-01` 和 `audio-scalar-runtime-p2-01`。目标应用复测尚待完成。

AudioManager 采用独立 facade。固定平台必需 adapter 核验全部允许签名，只放开模式/铃声/流音量/静音/音频设备/指定输出属性查询和有界 AudioDeviceCallback；其他实例方法明确拒绝。实际返回数据与初次设备回调来自系统 AudioManager，系统归因属于引擎 UID，不伪装独立系统音频身份。录音状态查询、音频焦点、路由、音量/模式修改、播放/录音控制都未授予。

每进程最多 16 个设备观察者。真实系统回调转到调用者 Handler 所在 Looper；没有指定 Handler 时用主线程。登记后才开放交付，取消先关闭交付再请求平台取消，晚到排队事件在执行时再检查注册状态。失败不制造取消成功，未确认记录继续关闭保留。夹具检查真实设备查询、初次回调、线程归属、重复注册/取消和写入拒绝；未插拔真实外接音频设备，不宣称已验证持续热插拔或所有取消竞争。
