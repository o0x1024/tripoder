# H2a v2：自有代码页的准备、发布与退休

日期：2026-10-15。范围：独立 non-debuggable 探针、自有 ELF 专属页、固定 `uint64_t(uint64_t)` ABI、协作调用域。本轮真机验收已通过；H2 的通用能力仍未完成。旧文件页写入方案及 EACCES 记录保留在 [H2a 初版记录](self-hook-native-h2a.md)。

## 审查结论

上一版把原 ELF 文件页同时作为来源证明和可修改的执行存储。真机已证明，该页发生 private COW 后恢复 RX 被拒绝，而运行时新建匿名页 RW→RX 可行。两种页的来源、生命周期和权限契约不同，不能把后一项实验当成前一项成功，也不能仅重试原权限切换。

新版本只有一种发布模型：保留原文件身份作为来源，运行时为每个版本新建匿名页；页内所有指令按最终执行地址规划，完成 RW→RX 后，在协作域排空期间移动到已经拥有的目标地址。原 ELF 文件页不写脏，不请求 RWX，不改变系统策略，不切换其他后端。实际调用仍跳到原 `dlsym` 入口地址。

这依赖完整页面所有权。fixture 的入口、跳板和中转各独占一页，无构造/析构器、未知调用者、信号入口或异常展开。通用客体代码页不满足这些条件，明确不支持。不能把 `/proc/self/smaps` 的匿名属性当成可对抗同进程任意恶意修改的唯一身份；所有权来自模块租约、私有页句柄、唯一修改锁及完整字节复验的组合。

## 唯一发布流程

1. `open` 验证模块、页位置、完整内容和文件 inode/device/offset。只读打开包内原 ELF，fstat 匹配来源，并为入口和跳板各保留一个独立的 RX 文件视图。文件视图只用于恢复，不在临时地址执行；保持模块 dlopen 租约。
2. 新建一页匿名 RW，核验无 X，填满 4096 字节，按最终地址生成分支和跳板，清理缓存；mprotect 为 RX，核验无 W 以及全部内容。
3. 安装/停用前关闭登记入口，等待已登记调用全部返回；100 ms 超时保持原状态。当前实现持有修改锁准备页，调用延迟尚未优化。
4. 复验目标页身份和预期内容，使用 `mremap(MREMAP_MAYMOVE | MREMAP_FIXED)` 将准备好的 RX 页移到唯一授权地址；在最终地址同步缓存，复验匿名 RX 和完整内容，随后发布 epoch、开放登记。执行线程进入前执行 ISB。
5. 停用发布包含原指令的匿名 RX 版本。关闭时再次排空，将保留的原 RX 文件视图移回原地址，核验来源及完整原字节，然后清空回调指针、释放模块租约。每个候选页及旧版本即时退休，没有无限累积的跳板。

`MREMAP_FIXED` 会移除目标范围内的映射，因此只在本模块的专属地址上使用；不能假设 syscall 失败时目标未变。准备阶段失败可释放候选页并明确返回；进入固定地址发布后，任何失败或验证不一致均终止独立进程，不开放未知执行状态。[Linux mremap 接口约定](https://man7.org/linux/man-pages/man2/mremap.2.html)。

来源文件视图采用只读 private 映射，文件描述符关闭后视图仍持有映射；原包文件 SHA 在运行前后复核。[Linux mmap 接口约定](https://man7.org/linux/man-pages/man2/mmap.2.html)。

不宣称跨所有线程的原子替换；成立条件是无调用者执行或访问被替换页。mutex 覆盖登记先于函数入口的窗口，计数持续到回调及原函数返回；CPU 指令同步沿用 [Arm 的跨线程说明](https://developer.arm.com/community/arm-community-blogs/b/architectures-and-processors-blog/posts/caches-self-modifying-code-working-with-threads)。

## 必须验证的边界

- 真实入口地址不变，原函数 7→8，Hook 后 7→108，原调用恰好一次，停用恢复；保留 BTI 指令，但页级 BTI/MTE 仍拒绝，PAC/异常/信号尚不支持。
- 同一实际入口地址的 prepared / active / disabled / restored 映射快照与 runId、源码、APK、fixture SHA 绑定；关闭恢复真实文件 inode/device/offset，原 ELF 文件 SHA 不变。
- 人为拒绝一个尚未发布的候选页，确认原字节可执行、epoch/变更次数不变，候选页释放；该注入计数与真实内核 errno 分开报告。
- 真实回调阻塞时排空超时不变更；四线程执行并发安装/停用 50 轮，检查值、epoch 状态、原调用次数、errno 和重入拒绝。
- 显式观察租约仅用于 owner close 后读取恢复映射，随后立即释放；必须观察实际卸载，重载新 generation，旧 token 不能操作新模块。
- 两个保存的原文件视图，加一个准备页，临时视图峰值 3 页；最多两个已发布匿名页。完整关闭后两类页计数均归零。实例仍最多 1024 次变更；没有生产延迟或吞吐承诺。

## 尚未解决的问题

该模型只能说明专属代码页的正常进程内发布可行。任意 ELF 的共享代码页、未知线程 PC/返回地址、模块被第三方卸载、结构体/varargs ABI、异常与信号、BTI/PAC/MTE、ART/JIT/AOT 和原反射帧均仍是独立风险门槛。临时内存归零的计数还需与 maps/卸载证据共同判断；它不是整个进程无泄漏或长期稳定性证明。

下一步优先做 H3a：固定 libart 身份下的进程内可访问性、方法身份、线程状态和原调用语义探针，再决定 ART 拦截路径；同时保持 H2 通用 Native 和故障生命周期未完成。H4–H6 的 Runtime 适配迁移仍须等待这些门槛，不提前删除产品 Frida。
